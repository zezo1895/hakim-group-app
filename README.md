# الدليل الشامل لمشروع Hakim Group App

هذا الملف يوثق **كل تفصيلة حرفياً** تمت في المشروع منذ بدايته وحتى اللحظة، ليكون مرجعاً تقنياً وتاريخياً شاملاً للكود وقاعدة البيانات.

## 1. الهيكل التقني للمشروع (Architecture)
### أ. تطبيق الموبايل (Front-End)
* **التقنية:** React Native باستخدام إطار عمل **Expo (SDK 57)**.
* **إدارة الحزم والرفع:** استخدام `EAS (Expo Application Services)` لعمل Builds (Development و Production) وتخريج ملفات APK.
* **المسار المحلي:** `C:\Users\Desgin\Desktop\My Projects\hakim-group-app`
* **الملاحة (Navigation):** `react-navigation/native-stack` للتنقل بين الشاشات.
* **حفظ البيانات محلياً (Offline Storage):** استخدام `AsyncStorage` لحفظ المنتجات، الأقسام، وحالة التحميل لتشغيل التطبيق بدون إنترنت بعد أول مرة.
* **التصميم (UI):** نظام تصميم ثابت (Design System) يعتمد على ملف `src/theme/index.js` (ألوان حكيم جروب الأساسية، المسافات، الظلال).

### ب. الخادم وقاعدة البيانات (Back-End)
* **التقنية:** Node.js مع Express.
* **قاعدة البيانات:** MySQL مستضافة على خوادم **Railway** السحابية.
* **المسار المحلي:** `C:\Users\Desgin\Desktop\My Projects\hakim-clean\hakim-clean\backend`
* **لوحة التحكم (Admin Panel):** واجهات برمجية (APIs) لإضافة المنتجات، الفيديوهات، والتحكم في إصدارات التطبيق.

## 2. الميزات الأساسية التي تم برمجتها (Features)
1. **نظام المزامنة والتخزين المؤقت (Offline Sync & Caching):**
   * عند فتح التطبيق لأول مرة، يقوم بسحب كافة المنتجات والصور من الخادم.
   * يتم تخزين البيانات النصية في `AsyncStorage`.
   * يتم تحميل الصور وتخزينها كملفات فعلية باستخدام `expo-file-system`.
   * تم تعديل نظام المزامنة مؤخراً بحيث **يستحيل الدخول للتطبيق إلا بعد اكتمال تحميل 100% من الصور**. إذا انقطع التحميل، يتم استكماله من نقطة التوقف بدلاً من البدء من الصفر.

2. **نظام التحديث الإجباري (Force Update):**
   * تم برمجة شاشة تمنع المستخدم من دخول التطبيق وتجبره على تحميل النسخة الجديدة إذا اختلفت نسخته عن النسخة المسجلة في قاعدة البيانات (`app_version` table).
   * **باب سري (Backdoor):** تم برمجة ضغطة مطولة لمدة 3 ثواني على زر التحديث لتخطي الشاشة في حالات الطوارئ والاختبار.
   * تم ربط النظام مع **GitHub Actions** ليقوم برفع رقم الإصدار تلقائياً في قاعدة البيانات عند صدور أي Release جديد.

3. **معرض المنتجات والتفاصيل (Products Catalog):**
   * عرض شبكي (Grid) متجاوب مع الهواتف والتابلت.
   * إمكانية البحث السريع (Debounced Search).
   * فلترة المنتجات حسب (ساخن/بارد) ونوع الخامة (PP, PS, PET, إلخ).
   * شاشة تفاصيل المنتج تعرض المنتجات المرتبطة (الأغطية - Lids / المنتجات المشابهة - Siblings).

4. **تعدد اللغات والمظهر الداكن (Dark Mode & i18n):**

   * تم برمجة نظام لدعم اللغتين العربية والإنجليزية.
   * تم ربط ترجمة المنتجات بخدمة ذكاء اصطناعي (Gemini) في الباك إند لترجمة مئات المنتجات أوتوماتيكياً.

## 3. أبرز المشاكل التي واجهتنا وكيف تم حلها (Bug Fixes)
1. **مشكلة الشاشة الحمراء وانهيار التطبيق (App Crash):**
   * **السبب:** تداخل في مكتبة `react-native-reanimated` بعد إضافة إعدادات Babel. أيضاً وجود المتغير `t` (الخاص بالترجمة) في مساحات عامة خارج مكونات React.
   * **الحل:** كتابة سكريبت محلي استبدل كل الأخطاء البرمجية ونظف الملفات، وتم إرجاع الكود لنسخة 1.1.4 المستقرة لحين الحاجة للتحديث.

2. **مشكلة صور المنتجات التي لا تظهر:**
   * **السبب:** بعض روابط الصور كانت تحتوي على مسافات أو رموز عربية، مما يجعل نظام تشغيل أندرويد يرفض تحميلها.
   * **الحل:** إضافة `encodeURI()` لمعالجة روابط الصور برمجياً قبل تحميلها.

3. **مشكلة تكرار الأكواد (Duplicate Hooks):**
   * **السبب:** خطأ آلي تسبب في تكرار تعريف `const { t } = useTranslation()` في جميع الملفات.
   * **الحل:** تم بناء سكريبت `fix_duplicates.js` لمسح كافة التكرارات في ثوانٍ معدودة وتنظيف مساحة العمل بالكامل.

4. **فشل البناء على جيت هاب (EAS Build Failure):**
   * **السبب:** نقص مكتبة `babel-preset-expo` في ملف `package.json`.
   * **الحل:** تم تثبيتها كـ Dev Dependency ورفعها، مما جعل الـ Build ينجح.
